# Grounding bill summaries in approved news evidence

Bill summary prompts include approved article text alongside statutory material. Snapshots bind evidence identity to unique batch attempts, isolating successive generations.

## Why generation requires approved article evidence

Unchecked web search snippets risk introducing hallucinations or unverified assertions into public legislation summaries.

Requiring explicit administrative approval via [[app/models/bill_news_article.rb#BillNewsArticle]] and attributable full text via [[app/models/news_article_text_version.rb#NewsArticleTextVersion]] limits [[app/services/bill_summary_prompt_builder.rb#BillSummaryPromptBuilder]] to approved records with usable text. Approval is an editorial decision, not proof that the reporting is true. Articles lacking full text or lacking administrative confirmation remain excluded from synthesis, preventing ungrounded claims from entering the model prompt.

Text extraction and manual entry occasionally produce records containing only whitespace characters. Treating whitespace-only text versions as effectively textless both in the synthesis-eligibility scope and within prompt construction prevents empty source tags from diluting prompt context and ensures the model is grounded solely in substantive reporting.

## Why prompt injection is bounded by an untrusted enclosure

External news text is third-party material that can contain formatting anomalies, adversarial text, or prompt injection instructions.

Wrapping news articles inside a randomized `<NEWS-ARTICLES-BOUNDARY-...>` enclosure generated by [[app/services/bill_summary_prompt_builder.rb#BillSummaryPromptBuilder]] neutralizes raw code fences and isolates third-party content. Enclosing individual `<source>` tags with explicit association identifiers, text version identifiers, and match classifications provides verifiable structural context while constraining prompt length within fixed character budgets.

## Why source uses and drafts precede publication gating

Generated summaries pass through [[news-gate|publication gating]], which decides whether a revision is published or retained as a draft.

[[app/services/news_article_source_snapshot_service.rb#NewsArticleSourceSnapshotService]] captures immutable source entries. Each snapshot is bound to its specific batch attempt through `SummaryRunMarker.batch_pending_id` and `SummaryRunMarker.batch_run_id`. [[app/services/summary_batch_result_persister.rb#SummaryBatchResultPersister]] resolves the exact capture associated with that batch run, ensuring that successive submissions maintain isolated source-use collections and that out-of-order or late-returning responses evaluate their own locked evidence version rather than colliding with subsequent runs.

Model responses can contain invalid source references. [[app/services/news_summary_manifest_validator.rb#NewsSummaryManifestValidator]] validates the raw manifest envelope before candidate records are persisted, rejecting any output with invalid source references as a whole rather than pruning partial entries. [[news-gate#Why ungrounded generations are quarantined as draft revisions]] describes the resulting publication limitation.
