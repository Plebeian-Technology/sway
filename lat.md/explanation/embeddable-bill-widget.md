# Embeddable bill widget

The embeddable bill widget allows newsrooms to embed an interactive Sway bill card within articles while protecting Sway's single Raspberry Pi infrastructure from high traffic volumes.

Related discussions include [[client-caches-and-identity]] and [[content-security-policy]].

## Iframe delivery model

Sway delivers the bill widget as a responsive sandboxed iframe rather than a client-side JavaScript snippet or web component.

Newsrooms enforce strict Content Security Policies, scripts filtering, and KSES sanitization within their content management systems. Sandboxed iframes isolate styling, avoid cross-origin resource sharing requirements, and prevent third-party script liabilities for newsroom partners.

## Content Security Policy carve-out

The embed route overrides Sway's default clickjacking protection to permit framing by external partner newsrooms while retaining all core policy directives.

While the primary application enforces `Content-Security-Policy: frame-ancestors 'none'`, `Embed::BaseController` in [[app/controllers/embed/base_controller.rb]] uses Rails's `content_security_policy` DSL with `policy.frame_ancestors "*"` and `content_security_policy_report_only false`, and deletes `X-Frame-Options`. Using the controller DSL rather than assigning the header string directly preserves `default-src 'self'`, `script-src`, and `object-src 'none'` on `/embed/bills/:id` while scoping cross-origin framing to the embed surface.

## CDN caching posture and hardware protection

Public edge caching shields the single Raspberry Pi production server from traffic spikes generated by newsroom readers.

Sway runs production on a single Raspberry Pi behind Cloudflare Tunnel. Embed responses emit `Cache-Control: public, max-age=60, s-maxage=300, stale-while-revalidate=600` and `Vary: Accept, X-Inertia`, and `Embed::BillsController#show` in [[app/controllers/embed/bills_controller.rb]] includes `X-Inertia` presence in conditional `ETag` evaluation so HTML and Inertia JSON responses never collide in browser or edge caches.

## Referral tracking and attribution

Partner referral tracking operates across the iframe sandbox boundary by encoding attribution parameters directly in call-to-action links.

Modern browsers partition third-party cookies inside cross-origin iframes. Outbound clicks on the "Act on this bill" button open the full bill page in a new first-party tab with partner and referral parameters preserved, allowing first-party session attribution upon landing.

## Alba serialization

The widget serialization provides a strictly reader-agnostic payload containing public metadata and aggregate vote totals.

[[app/serializers/embed_bill_resource.rb#EmbedBillResource]] serializes bill identifiers, titles, summaries, locale data, vote counts, and deep links without exposing user identity, user votes, session cookies, or personally identifiable information.

Below ten voters the For and Against counts are withheld: [[voter-privacy-threshold#The embed widget withholds counts on the server]].

## Controller implementation

`Embed::BillsController` and `Embed::BaseController` provide stateless endpoints isolated from authenticated session machinery.

`Embed::BaseController` in [[app/controllers/embed/base_controller.rb]] inherits directly from `ActionController::Base`, skipping session cookies via both `prepend_before_action` and `after_action` and omitting CSRF meta tags from [[app/views/layouts/embed.html.erb]] so no session-specific token is cached publicly. `Embed::BillsController` in [[app/controllers/embed/bills_controller.rb]] handles conditional GET evaluation and passes serialized props to Inertia.

## Request verification

Comprehensive request specifications verify caching headers, frame permissions, conditional GET status, and referral parameter preservation.

Automated tests in `spec/requests/embed/bills_spec.rb` and `spec/requests/serializer_whitelists_spec.rb` validate response status codes, header configurations, and serialized attribute contracts.
