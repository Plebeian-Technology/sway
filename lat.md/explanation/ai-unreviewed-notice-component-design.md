# AiUnreviewedNotice component design

`AiUnreviewedNotice` informs readers when summary text or organizational rationale was generated by machine intelligence without human revision.

The component attaches attribution notices beneath legislative summaries and organization positions, keeping notice presentation consistent across diverse page layouts.

## Why the notice sentence lives in PARITY_COPY rather than component props

`PARITY_COPY.bill.content.aiUnreviewedNotice` centralizes unreviewed attribution phrasing so web and mobile readers render identical disclosure wording.

The server transmits an unreviewed boolean flag alongside bill summaries and organization positions. [[app/frontend/sway_constants/parityCopy.ts#PARITY_COPY]] holds the notice sentence so that [[app/frontend/components/bill/AiUnreviewedNotice.tsx#AiUnreviewedNotice]] and mobile screens render identical copy without embedding duplicate strings across layouts.

## The server sends a derived boolean, not the source text

Bill and organization-position payloads send whether the displayed text remains unreviewed, while clients build the notice sentence from shared copy.

[[app/models/bill.rb#Bill#summary_ai_unreviewed?]] supplies the same flag on the bill page and API shapes; the summary string itself never carries the notice. [[app/models/organization_bill_position.rb#OrganizationBillPosition#summary_ai_unreviewed?]] compares the public summary with the original `ai_summary`, but [[app/models/organization_bill_position.rb#OrganizationBillPosition#to_builder]] sends only the predicate and never the original model text.

The membership page builds its position props in [[app/controllers/organizations/base_controller.rb#BaseController#membership_as_props]], so it adds `summary_ai_unreviewed` explicitly. Omitting that derived value would leave this hand-built response without the notice flag.

## The pending-summary sentinel is not published AI text

[[app/models/bill.rb#Bill#SUMMARY_PLACEHOLDER]] is the shared sentinel written by [[app/services/legislation_ingestion_service.rb#LegislationIngestionService]] when ingestion has no summary. [[app/models/bill.rb#Bill#summary_ai_unreviewed?]] returns false for that sentinel before comparing published revisions or stored model output, so the pending text does not receive an AI attribution notice.

## One component for every such piece of text

Two kinds of text carry this notice: the bill summary, and each organization's reason for its position.

Several components render each kind, one per bill layout. Typing the sentence out at every call site would get it reworded at all but one of them over time. No count of call sites is kept in this component on purpose — a number in a comment goes stale the moment a new bill layout is added.

## The notice is never part of the text

The server sends a flag beside the text, and this component renders the sentence from that flag.

A person who revises the text removes the notice automatically, with no string to strip by hand. Every other reader of the text — the mobile app, the JSON API — decides for itself how to show the same flag, rather than inheriting a hardcoded sentence baked into the text itself.

It renders nothing when the flag is false, so a caller can pass the flag straight through with no condition of its own.

## Why BillSummaryMarkdown.tsx attaches the notice, not each bill layout

`aiUnreviewed` is true when the summary is a machine's words that no person revised — the notice then goes under it.

The notice is attached in `BillSummaryMarkdown.tsx`, and not in the bill layouts. Every layout renders the summary through this component; adding the sentence to each layout instead would mean all but one of them get it.

The prop is optional so the admin previews that use this component show the plain text they preview. The component also enforces URL scheme safety across rendered markdown links: only standard web protocols are permitted as navigable anchors, and unsafe schemes such as `file:`, `javascript:`, and `data:` are rendered as inert text.

## Why OrgPositionSummary.tsx is a component for one paragraph

One organization's reason for its position on a bill carries this notice when a machine wrote the reason and no person revised it.

Several screens render this text, and each styles it differently: the bill layouts, the organization page, and the organization's own position card. Adding the notice at every site by hand would mean all but one end up with it. The `className` stays with the caller, so each layout keeps its own look. The notice does not. Searching for `OrgPositionSummary` locates every caller.

The summary text is markdown, rendered through the lazy bill-summary renderer, so a position's lists, emphasis and links display as written. Its `prefix` prop — the words a layout puts in front of the summary ("In support.", "In opposition.") — exists as a prop, and not as a reason to let those layouts write their own paragraph instead of using this component: a component that all but two callers go through is how those two get missed.

## What the test file's examples are pinning down

The component test suite pins down the notice rendered under text a machine wrote that nobody has revised.

The rule these examples hold down is that the notice follows the server's answer for each piece of text, and is never part of the text itself. A test that only rendered it with the flag on would pass whether or not the flag was read at all, so every case below is paired with its opposite.
